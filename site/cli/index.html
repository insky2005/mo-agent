Mo CLI · 个人工作台

把想法变成任务卡，
派给任意 Agent 干完。

你写卡，人批准，Agent 执行，mo 按你定的验收标准结算，全过程记账。 文件即状态，不依赖常驻服务；装了桌面端的话，任务卡也能在手机上批。

装 Mo CLI 看工作流

一张卡的一生

没有数据库，没有常驻进程；状态就在文件里，可以 grep、可以 diff、可以进 git。

建卡

mo task create 写下交付物、验收标准与边界。缺验收会告警：卡能建，但结论得自己看。

人批准

mo task confirm 发起请求，只有人能批（终端或手机）。批准前改卡会让这次批准作废。

派单

mo task dispatch 派给内置执行者或任意命令；--detach 后台跑，不占终端。

验收

执行者交回执，mo 亲自跑验收（run: / check: / human:），退出码 0 但没有回执不算完成。

常用命令

命令以 mo help 为准：mo help --all 看全部分组，mo help <组> 看细节。

# 认领项目、看执行者
mo project create
mo worker list

# 建卡（TTY 下会问「现在批准并派单吗」）
mo task create --title "加筛选" \
  --deliverable "tasks.html 有筛选栏" \
  --verify "run:npm test" --worker claude-headless

# 看状态 / 收结果 / 查账本
mo task show <id>
mo inbox pull
mo ledger query --task <id>

不想开外部 Agent？mo 自带一个指挥台

内置主 Agent，只分派、不动手——它没有 shell、不能写文件，想干活只能派单。

01

没有手

只有 read / grep / find / ls 与 mo 的 MCP 工具；运行时无法收窄工具面就拒绝启动。这条边界靠启动参数，不靠提示词。

02

只做分派

理解意图、拆任务卡、派人，按账本事实汇报。过程文档自己记（note_write），交付物一律派单。

03

手机也能对话

指挥台以 role: router 进会话列表，手机能给它发话；批准仍然只能由人做。

启用

会装一份私有运行时（约 150MB，版本锁定），凭据落 0600，可用 --no-test 跳过测通。

mo router setup --provider deepseek --model deepseek-flash --key sk-...
mo router start

安装

单文件二进制，不需要 Node。装完先跑 mo setup（幂等，会问你要不要配指挥台）。

一条命令

macOS / Linux 装到 ~/.local/bin/mo；Windows 装到 %USERPROFILE%\.local\bin\mo.exe。需要同时给 Agent 装技能就加 --with-skill。

# macOS / Linux
curl -fsSL https://raw.githubusercontent.com/insky2005/mo-agent/main/installer/get-cli.sh | bash

# Windows（PowerShell）
powershell -ExecutionPolicy Bypass -c "irm https://raw.githubusercontent.com/insky2005/mo-agent/main/installer/get-cli.ps1 | iex"

# 装完
mo setup
mo doctor
平台状态说明
macOS可用Apple Silicon / Intel 都有单文件产物
Linux可用x64 / arm64
Windows适配中执行者模板与安装器已落地，真机验收待补

和桌面端是什么关系

不是两个产品，是一个人的两种用法：桌面端替你盯着、把决定递给你；Mo CLI 负责把活派出去、按标准结算。

  • 同一份数据：卡、回执、账本、待批请求都在 ~/.mo-agent/，手机上批的就是 Mo CLI 建的卡。
  • 没有桌面端也能用：mo serve install 补齐 host，mo serve start 就能扫码配对、手机批准与监控。
  • 没有 Mo CLI 也能用：只装桌面端，就把 mo 当成 Agent 小监理——只观察、只通知、只批准。
  • 不必二选一：先装桌面端看效果，再回来用 Mo CLI 把活派出去，是同一条链路。
