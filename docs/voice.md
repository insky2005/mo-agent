# 语音免手确认

目标：**不打字、不按键**。Agent 卡在授权时，host 用 TTS 把动作、目标和口令念出来；你复述口令，它才放行。

设计取舍见 [ADR-0002](adr/adr-0002-hands-free-voice.md)。本文是使用与排障手册。

## 架构

    host (Node) ──TCP 127.0.0.1──► mo-agent 语音.app（常驻 helper）
                                        │ AVAudioEngine 录音 + VAD 断句
                                        ▼
                                   utterance.wav
                                        │
                                        ▼
                              whisper.cpp（本机离线）
                                        │ 文本 + 置信度
                                        ▼
                              两段式确认状态机 ──► approvals 中枢
                                        │
    say → .aiff → afplay ───────────────┘（播报草稿与提示音）

- **helper**：`mo-agent 语音.app` 是唯一直接碰麦克风的进程。host 通过 `127.0.0.1` 的一行 JSON 协议发
  `ping / selftest / record / quit`；端口和随机 token 写在 `~/.mo-agent/voice-bridge.json`（0600）。
  helper 空闲 5 分钟自动退出，host 每分钟 ping 一次保持热状态。
- **识别**：whisper.cpp + `ggml-small-q8_0`，全部在本机完成，音频不上传、不落长期存储；
  临时 wav 识别完立即删除。语音命令会带一组命令词作为初始提示词，减少「会话→绘画」这类同音错；
  确认阶段刻意不带提示词，避免把 TTS 回读的「确认吗」偏置成「确认」。
- **播报**：`say` 先合成 aiff，再用 `afplay` 阻塞播完，最后留 150ms 收尾，避免蓝牙路由切换吃掉尾音。
- **串行**：播报与录音严格互斥；同一时间只处理一个语音请求。

## 权限（macOS TCC）

只需要给 **mo-agent 语音.app** 麦克风权限，不需要给外层 mo-agent.app。

- 首次录音会弹系统授权框，点「允许」即可；
- 没弹窗时：系统设置 → 隐私与安全性 → 麦克风 → 打开「mo-agent 语音」；
- 未授权时 helper 返回 `mic-denied`，host 日志写「语音未启用：麦克风权限被拒绝」，不会放行任何操作。

重建或升级会重置权限，原因见下文「升级后权限没了」。

## 使用

1. `./scripts/install-desktop.sh` 安装并启动桌面 App；
2. 菜单栏托盘 → **语音** → 勾选 **「启用语音」**（会重启 host）；
3. 首次授权：系统弹出「mo-agent 语音」麦克风请求，点允许；
4. Agent 卡住时，host 念出「批准 <动作> <目标>，请复述口令 4 7 2 9」；
5. 听到提示音后复述口令。说「拒绝」可直接拒绝；说「重复」会重念草稿。

同一子菜单还有：

- **麦克风权限设置…**：直接打开系统设置的麦克风页；
- **语音命令**：点一次、说一条命令（状态 / 暂停 / 继续 / 切换会话），结果显示在语音浮层；
- **语音口述任务**：点一次、说一段任务，先成草稿、回读，再说「确认发送」才发给当前关注会话；
- **语音测试**：念一个随机口令，让你复述后返回结果，用来验证整条链路。

规则：

- 最多 **3 次尝试**（`MO_AGENT_VOICE_ATTEMPTS` 可改）；口令错、低置信度、超时、听不懂都只重试或丢弃，
  **绝不返回放行**；
- 超时、取消、麦克风不可用时不落任何决策，请求仍留给手机或 broker 超时处理；
- 授权类不叠加第三次确认：草稿回读 + 口令复述就是最终确认；
- 语音子菜单的勾选状态存在 `~/.mo-agent/voice.json`，取消勾选会重启 host 并关闭语音。

## P1 语音命令

**触发**：托盘「语音」→「语音命令」。这是 **click-to-talk**：点一次、听一条命令，不是唤醒词，也不常开麦克风。
唤醒词与免按键唤起留到 P3。
- **浮层显示**：命令期间会在最上层出现一个磨砂半透明浮层（可拖动、不抢焦点）：
  实时显示「正在听 → 听到的原文 → 解析出的意图 → 确认回读 → 最终结果」。
  最终结果先显示，再 TTS 播报；浮层会在结束后自动隐藏，不用弹框。
  第一次出现默认屏幕居中；拖动后位置写入 `~/.mo-agent/voice-overlay.json`，下次打开还在原处。
- **提示音**：每次开始录音都会播放一个 120ms 的短提示音，不受是否检测到说话影响。
  提示音很短，而且 gate 在提示音**之前**打开，所以提示音一响就开口也不会漏掉第一个字。
  如果麦克风权限未授予，host 会直接提示去系统设置授权，不会让你干等提示音。

| 命令 | 示例 | 副作用 | 确认 |
|---|---|---|---|
| 状态查询 | 汇报状态 / 现在怎么样 / 几个会话 | 无 | 不需要 |
| 暂停 | 暂停 / 停一下 / 静音 | 静音语音播报与语音审批，默认 15 分钟 | 回读 + 说「确认」 |
| 继续 | 继续 / 恢复 / 取消静音 | 取消静音 | 回读 + 说「确认」 |
| 切换会话 | 切到第 2 个 / 切换到登录页 | 设置「当前关注会话」 | 回读 + 说「确认」 |
| 帮助 | 你能做什么 / 帮助 | 无 | 不需要 |

边界（按 ADR-0001/0002 的观察优先原则）：

- **暂停不是 SIGSTOP**：只关「语音播报 + 语音接审批」，不暂停 Claude Code / DSH 进程。
  静音期间审批仍进 pending，手机和终端照常处理；状态查询会报告还剩多少分钟。
  静音也不影响手机通知。
- **切换不是切前台**：host 没有前台窗口，只设置 `voiceTargetSessionId`；后续状态查询围绕它汇报，
  P2 口述任务默认发给它。审批归属不变，仍是逐请求的。
- **歧义不执行**：一句话同时像两类命令（例如「暂停一下看看状态」）、低置信度、未知说法，
  一律只提示没听懂，不做任何动作。
- **明确确认**：有副作用的命令先 TTS 回读动作，再听一次「确认 / 取消」；数字口令只留给审批。
- **开麦容错**：每次命令先预热 helper/麦克风权限，TTS 播完等 500ms 再开麦；第一次没录到会
  自动再听一次，仍然只认明确命令/确认。
- **繁体归一**：whisper 常把中文识别成繁体（例如「匯報狀態」「暫停」），文本规则会先归一成简体
  再解析；归一表覆盖语音命令与确认词常见字。
- 找不到会话或匹配到多个时列出候选，不猜、不切换。
- 「当前关注会话」和「静音截止时间」都在 host 内存里，重启 host 会复位。

日志里每次命令会留下完整链路（默认 info 级别）：

    语音命令: 收到本机请求
    语音命令: 麦克风会话已就绪 启动=2200ms 缓冲=64 峰值=0.1438
    语音命令: 开始监听 超时=15000ms 最低置信度=0.35 最多尝试=2 次 播报后延迟=500ms
    语音命令: 正在听（浮层事件）
    语音命令: 听到「汇报状态」 置信度=0.95（浮层事件）
    语音命令: 预热 完成 耗时=12ms 设备=HUAWEI FreeBuds SE 3 麦克风=已授权
    语音命令: 监听完成 第1次 耗时=1280ms 文本=「匯報狀態」 置信度=0.87
    语音命令: 状态 会话=7 运行=1 等待=0 待授权=0 静音=否 关注=-
    语音命令: 文本=「匯報狀態」 intent=status 结果=reported 置信度=0.87 归一=「汇报状态」
    语音命令: 请求结束 耗时=1650ms ok=true intent=status

需要确认的命令还会记录：

    语音命令: 需要确认 intent=pause 回读=「要暂停语音播报与语音审批 15 分钟，确认吗？」
    语音命令: 确认输入 文本=「确认」 置信度=1.00 判定=confirm 耗时=760ms
    语音命令: 已执行 action=muted mutedUntil=1760000000000 targetSessionId=-
    语音命令: 文本=「暂停」 intent=pause 结果=muted 15min 置信度=1.00 归一=「暂停」

未知/歧义会带上原因，方便判断是识别错还是匹配没覆盖：

    语音命令: 文本=「今天天气不错」 intent=unknown 结果=unknown 置信度=0.91 归一=「今天天气不错」 原因=no-match
    语音命令: 文本=「暂停一下看看状态」 intent=unknown 结果=unknown 置信度=0.88 归一=「暂停一下看看状态」 原因=ambiguous

更细的「播报原文」「解析目标」在 debug 级别（`MO_AGENT_LOG_LEVEL=debug` 或启动参数 `--log-level debug`）：

    语音命令: 播报「请等提示音，然后说命令。」
    语音命令: 解析 intent=switch 归一=「切到第2个」 目标={"kind":"index","index":2}

## P2 语音口述任务

**触发**：托盘「语音」→「语音口述任务」。仍然是 **click-to-talk**：点一次、说一段、确认发送。
不做唤醒词、不常开麦克风、不在后台偷偷继续录；失败后由用户重新点一次。

流程：

1. host 打开音频会话，浮层显示「正在准备麦克风」；
2. 提示「请说你要交给 Agent 的内容，说完停一下」，播放 120ms 提示音；
3. 识别完成 → **先成草稿，绝不直接发送**；浮层显示草稿全文、目标会话、字数；
4. TTS 回读草稿（40 字以内全文；超过 40 字念前 40 字 + 共 N 个字）；
5. 只有说「确认发送」/「发送」/「确认发布」才发送；说「重说」丢弃并重录一次；说「取消」丢弃；
6. 发送只走 `dsh.prompt(sessionId, text, mode)` 一次，成功时浮层先显示「已发送给 X」再播报；
7. 关闭音频会话，浮层自动隐藏。

**目标会话**沿用 P1 的「当前关注会话」，规则固定为：

- 有焦点会话且在线：发给它；
- 没有焦点、但恰好 1 个活跃会话：自动选它，回读时明确说「发给 X」；
- 没有焦点且有多个 / 零个活跃会话：不发送，列出候选，提示先说「切到第几个」；
- 焦点会话已离线：不发送，列出候选；
- 目标在口述开始时捕获，中途切换关注会话不改变本次发送目标。

**确认必须严格**：口述只认带「发送/发布」动作的短句（`确认发送`、`发送`、`确认发布` 等），
「同意」「确定」「好」「可以」都不会发送。数字口令仍然只用于审批，不用于口述。

**任何不确定都不发送**：录音超时、低置信度、空文本、超过字数上限、目标不明确、
DSH 不可用、发送抛错或被拒绝，全部只显示原因、保留草稿，不自动重试、不换 Agent。

边界：

- **暂停语音不影响口述**：P1 的「暂停」只静音播报/语音审批，不阻止用户主动点「语音口述任务」；
- **口述不是通知**：结果不走 HMS / Webhook，只在浮层显示后播报；
- **不编辑**：不支持改一个字、删一句；错就「重说」重录整段（最多一次）；
- 不做流式口述、多会话广播、自动重试发送；仅 macOS。

录音参数：口述断句静音 1.6 秒、单次最长 30 秒、录音整体超时 45 秒；
确认阶段沿用 15 秒。审批和 P1 命令的默认参数（静音 1.1 秒、最长 12 秒）不变。

日志（默认 info，全文预览最多 200 字）：

    语音口述: 收到本机请求
    语音口述: 目标会话=登录页(session-1) 来源=focus
    语音口述: 识别完成 第1次 耗时=3200ms 字数=86 置信度=0.92
    语音口述: 草稿 目标=登录页 字数=86
    语音口述: 确认输入 文本=「确认发送」 判定=confirm
    语音口述: 已发送 目标=登录页(session-1) 字数=86 耗时=420ms
    语音口述: 请求结束 耗时=18300ms ok=true

未发送时会记录原因，例如 `原因=no-target|target-offline|ambiguous|timeout|cancel|low-confidence|too-long|send-failed`。

## 配置

`~/.mo-agent/voice.json`（由托盘写入）：

    { "enabled": true }

常用环境变量：

| 变量 | 默认 | 说明 |
|---|---|---|
| `MO_AGENT_VOICE` | 读 voice.json | `1` 强制开启，`0` 强制关闭 |
| `MO_AGENT_VOICE_ATTEMPTS` | 3 | 口令/识别失败后的最大尝试次数 |
| `MO_AGENT_VOICE_TIMEOUT_MS` | 15000 | 单次等待语音的时长（命令与确认共用） |
| `MO_AGENT_VOICE_MUTE_MINUTES` | 15 | 说「暂停」后静音语音播报/审批的时长 |
| `MO_AGENT_VOICE_LISTEN_DELAY_MS` | 500 | TTS 播完后、开麦前的等待；蓝牙耳机可调大 |
| `MO_AGENT_VOICE_DICTATE_MAX_CHARS` | 4000 | 口述草稿的最大字数；超过则不发送 |
| `MO_AGENT_WHISPER_MODEL` | 内置 small 模型 | 覆盖模型路径（开发或换模型用） |
| `MO_AGENT_VOICE_BRIDGE` | 包内 helper | 覆盖语音桥可执行文件路径 |
| `MO_AGENT_WHISPER_BIN` | 包内 whisper-cli | 覆盖 whisper 可执行文件路径 |
| `MO_AGENT_TTS_SETTLE_MS` | 150 | 播完后等待音频排空的余量 |
| `MO_AGENT_LOG_LEVEL` | info | host 日志级别；`debug` 会多记语音播报原文与解析细节 |
| `MO_AGENT_VOICE_SCRIPT` | 无 | 用脚本台词代替麦克风（调试） |
| `MO_AGENT_VOICE_NONCE` | 随机 | 固定口令（配合脚本调试） |
| `MO_AGENT_VOICE_DRY` | 无 | `1` 时只记录播报文本，不出声 |

## 日志

host 日志：`~/Library/Logs/mo-agent/host.log`，超过 5MB 轮转，保留 `host.log.1` ~ `host.log.3`。
桌面壳自己的启动/退出/崩溃信息写到同目录的 `desktop.log`（同样 5MB × 3），两者不再互相覆盖。

托盘「查看日志」打开的 `/logs` 页面看的是 host.log。语音相关行：

    第 1 次 语音输入: 「四七二九」 意图=approval 置信度=0.76 期望口令=4729
    第 1 次 语音输入置信度低: 「四七二九」 置信度=0.31 期望口令=4729
    语音输入失败: {"type":"asr-error",...}
    语音询问: Bash，口令 4729
    语音结果: allow
    语音测试，口令 4729
    语音测试结果: allow
    语音命令: 文本=「汇报状态」 intent=status 结果=reported
    语音命令: 文本=「暂停」 intent=pause 结果=muted 15min
    语音已启用
    语音未启用：麦克风权限被拒绝

怎么判断：

- **没听到**：没有「语音输入」行，只有「语音结果: timeout」——看提示音后是否真的开始说话；
- **听错**：有「语音输入」但文本不对，或置信度低——缩短口令、换安静环境；
- **权限问题**：启动时「语音未启用：麦克风权限被拒绝」，或 helper 返回 `mic-denied`；
- **桥没起来**：「语音桥自检失败」/「helper-unavailable」，检查 `~/.mo-agent/voice-bridge.json` 是否存在，
  以及 helper 的 .app 是否还在包内。

## 构建

    npm run voice:build          # 编译 Swift 桥（.build/mo-agent 语音.app）
    npm run voice:build:whisper  # whisper.cpp + ggml-small-q8_0（约 252MB，走 hf-mirror）
    ./scripts/build-desktop.sh   # 默认 WITH_VOICE=1，把上面两样一起打进 App

- 模型是**内置**的，不做首次下载：语音资源约 254MB，成品 App 约 282MB；不带语音约 46MB。
- 升级 App 会带全量模型重新解包，没有增量更新。
- 不想带语音：`WITH_VOICE=0 ./scripts/build-desktop.sh`（此时语音开关会报不可用）。
- 模型选择顺序：`MO_AGENT_WHISPER_MODEL` > `runtime/voice/models/ggml-small-q8_0.bin` >
  `runtime/voice/models/ggml-base.bin`。

## 开发诊断

`host/voice/p0.mjs` 是开发诊断工具，不是用户入口：

    npm run voice:demo   # 不碰麦克风，用脚本台词跑完整确认流程
    npm run voice:live   # 真实麦克风 + 真实 broker

`npm run voice:live` 首次会请求麦克风权限；未授权时返回 `mic-denied`，不会放行。

## 故障排查

### 没弹麦克风权限

- 确认用的是打包后的 App（裸命令行进程访问麦克风会被 macOS 直接终止）；
- 系统设置 → 隐私与安全性 → 麦克风，看「mo-agent 语音」是否在列表里；
- 重装后系统可能仍记着旧签名副本，先彻底退出再启动；仍不行时用
  `tccutil reset Microphone cn.mocampus.moagent.voicebridge` 重置后重试。

### 麦克风偶发没拉起 / 第一次没录到

现在命令链路会自动兜底：

1. 点「语音命令」后先打开音频会话（open 时请求麦克风权限），等输入通道有 buffer 在流；
2. TTS 播报期间引擎保持运行，整条命令（含确认）复用同一个会话，不再反复切 A2DP/HFP；
3. 每次录音开始**无条件先敲提示音**，再开麦；提示音就是“可以说了”的信号，不会因为静音时
   耳机输出全零而消失；
4. 第一次监听超时 / mic-silent / 路由变化会自动提示「请等提示音再说一次」并再听一次；
5. 确认阶段同样重试，但只有明确「确认」才执行；
6. 命令结束后关闭会话，麦克风指示灯熄灭；host 异常时 helper 120 秒后兜底关闭。

仍然频繁失败时，看日志区分：

- 「预热 失败:helper-unavailable」：helper 没起来，检查 `~/.mo-agent/voice-bridge.json`；
- 「麦克风=被拒绝」：系统设置里重新授权「mo-agent 语音」；
- 「监听失败 第1/2次 错误=timeout」：开麦成功但没检测到语音；
- 「错误=mic-silent 启动=3000ms 缓冲=0 峰值=0.0000」：输入通道在 3 秒内没有任何音频，
  通常是蓝牙耳机还没切到麦克风，或系统里麦克风被静音；重试通常能恢复；
- 「错误=route-changed」：录音期间音频路由被系统切走，重试；
- 「监听完成」但文本完全不对：是识别问题，不是开麦问题，见下面的识别质量。

监听完成日志会带录音诊断：

    语音命令: 监听完成 第1次 耗时=3200ms 文本=「汇报状态」 置信度=0.95 启动=680ms 缓冲=23 峰值=0.0312 提示音=Glass 采样率=16000 设备=HUAWEI FreeBuds SE 3

蓝牙耳机可把 `MO_AGENT_VOICE_LISTEN_DELAY_MS` 调到 800～1200；仍不稳时换有线/内置麦克风对比。

### 提示音后说话仍漏前几个字

提示音已改成 120ms 的短音，并且在提示音开始前就打开录音 gate；如果仍然漏字，通常是：

- 蓝牙耳机在提示音期间还在切 HFP，第一个音节被系统吞掉——改用有线/内置麦克风对照；
- 说话太靠近提示音起点，可以等“叮”的尾音再开口；
- 日志里看 `监听完成 … 提示音=beep-120ms`，确认提示音确实播了。

### 识别质量差

- whisper 输出繁体或同音字是常态，文本规则会先归一简体再匹配；
- 命令识别带提示词偏置（汇报状态/会话/切换等），能明显减少「会话→绘画」这类错误；
- 环境噪声大、离麦克风远、蓝牙 HFP 带宽低都会掉准确率；优先靠近麦克风、换有线耳机；
- 需要更高准确率时可换更大的 whisper 模型（`MO_AGENT_WHISPER_MODEL` 指到 `.bin`），代价是包体和延迟。

### 播报尾音被吃

- 默认已用「先合成再 afplay + 150ms 收尾」；蓝牙耳机切换 A2DP/HFP 仍可能慢，
  可调大 `MO_AGENT_TTS_SETTLE_MS`（如 300）；
- 有线耳机通常没有这个问题。

### 口令失败率高

- 先看日志里的「语音输入」行，确认是**没听到**还是**听错**；
- 口令用 4 位数字，逐位念，不要连读；
- 环境噪声大时靠近麦克风，或改用手机批准；
- 连续 3 次失败会放弃并交回手机，这是预期行为。

### 升级后权限没了

当前是 **ad-hoc 签名**。重建/升级后 macOS 可能把 helper 当成新 App，麦克风权限随之重置
（selftest 里 `micAuthorization` 会变回 `rawValue: 0`）。重新授权一次即可；正式 Developer ID
签名与「升级后权限保留」的验证暂缓。

重建语音桥后，下一次「语音命令」会触发系统麦克风授权框；点「允许」。
如果没有弹框，去系统设置 → 隐私与安全性 → 麦克风，勾选「mo-agent 语音」。

### 托盘里没有语音子菜单

确认运行的是带语音资源的构建（`WITH_VOICE=1`），并重启一次 App。仍没有时看 `desktop.log`。

## 已知限制

- 仅 macOS；
- 语音命令与语音口述都是 **click-to-talk**，还没有唤醒词/常开麦克风（P3）；
- 「暂停」只静音语音，不暂停 Agent；「切换」只设置关注会话，不切前台窗口；
- 从播报结束到真正开麦约 1 秒延迟（音频路由切换）；
- 模型约 252MB，随包分发；
- 中文技术词、路径仍可能听错，所以保留回读与 4 位口令；口令错或置信度低一律不放行。
