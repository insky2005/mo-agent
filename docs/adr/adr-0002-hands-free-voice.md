# ADR-0002：免手操作——语音优先、耳机直连

状态：**已采纳（P0 已实现；真机麦克风待一次系统授权）**　日期：2026-10-17

## 背景

ADR-0001 定下的主路径是「手机看状态 + 点按批准」。它解决的是"人离开电脑"，但没有解决"手被占用"：

- 炒菜、抱孩子、骑车、调试时满手是线；
- 掏出手机、解锁、找到卡片、点一下——四个动作，每个都在打断注意力；
- 用户明确提出的目标是：**解放双手，不打字、不按键。**

因此需要第三条交互通道：**声音进、声音出**。手机仍然是兜底与富信息界面，但不再是唯一入口。

## 决策

增加**语音直连**作为一等通道：蓝牙耳机（或任何麦克风/扬声器）**直接连电脑**，host 常驻监听，用语音完成四件事。

| 能力 | 说明 | 替代的旧动作 |
|---|---|---|
| **播报** | critical 通知用 TTS 念出来（谁、要什么、危险等级） | 掏手机看通知 |
| **语音决策** | 说「同意」/「拒绝」/「重复」 | 手机点按批准 |
| **语音指令** | 「汇报状态」「暂停」「继续」「切到第 2 个会话」 | 手机输入框 |
| **口述任务** | 一句话直接下发给选中的会话 | 键盘打字 |

目标形态：**戴着耳机干活，Agent 卡住了会开口问你；你回一句话，它继续。全程不碰任何设备。**

## 架构

    CoreAudio (耳机麦克风, VoiceProcessingIO 带 AEC)
        ↓
    VAD 断句 ──► 唤醒词（可选）──► 本地 ASR（whisper.cpp / Apple Speech）
        ↓
    意图路由 host/voice/intent
        ├─ approve / reject ──► approvals 中枢（复用现有 /local 决策）
        ├─ status / pause / resume / switch ──► 会话控制
        └─ dictate ──► 发送到目标会话（等同手机输入框）
        ↓
    TTS（say / AVSpeechSynthesizer）──► 耳机

约束：

- **音频不出本机**。ASR 默认本地推理，不接云端，不落盘原始音频（只留文本日志）。
- **播报与收音互斥**：TTS 期间暂停 ASR 或依赖 AEC，避免自己把自己触发。
- **复用现有决策链路**：语音只是另一种输入源，最终仍走同一个 approvals 中枢与审计日志，不新增放行旁路。

## 语音输入的两段式：先成稿，再发送

**语音不直接变成命令。** 所有语音输入先落成一份"草稿"，经用户二次确认后才交给 Agent：

    说话 ──► ASR 转写 ──► 草稿（不执行、不发送）
                              ↓
                   TTS 回读 + 「确认发送 / 重说 / 取消」
                              ↓
              确认 ──► 发送        其它 / 超时 ──► 丢弃

理由：

- **ASR 错一个字，任务就跑偏**，而确认比事后撤销便宜得多；
- 草稿是可见、可审计的：菜单栏与手机同时显示转写文本，用户一眼能核对；
- **超时默认丢弃，绝不自动发送**——延续 ADR-0001 的 fail-safe 方向：没听懂就当没听见。

确认词必须唯一、不含糊：只认「确认发送」/「重说」/「取消」，不接受「嗯」「行」「可以」。回读时念关键部分：

| 草稿类型 | 回读方式 |
|---|---|
| 短指令（< 40 字） | 全文回读 |
| 长指令 | 前 40 字 + 总字数 + "确认发送吗" |
| 含路径/文件名/数字 | 逐字念出这些片段，不省略 |

授权类不叠加第三次确认：草稿就是「批准 <动作> <目标>」，回读后用户复述 4 位口令即完成——**语义确认与防误触口令合并成一步**，避免"确认的确认"把人逼回手机。

## 安全：声音不是身份

这是本决策最重要的一条。ADR-0001 的底线是"绝不能在用户没有真实决策时放行"，而语音有两个新风险：**误识别**和**旁人代答**。

因此：

1. **拒绝永远安全**：说「拒绝」直接生效，无需确认。
2. **批准必须回读口令**：host 生成 4 位数字，TTS 念出（如「批准请复述 4 7 2」），用户复述一致才放行。
   - 这同时挡住 ASR 误识别、电视/旁人声音、以及"嗯"之类的含糊应答。
3. **低置信度一律转手机**：ASR 置信度不足、或指令有歧义时，不猜，发通知让用户用手机处理。
4. **危险操作分级**：rm -rf、写系统目录、推送远端等，除口令外还要 TTS 明确念出目标路径，用户复述路径才放行。
5. **物理静音**：菜单栏提供"停止聆听"，状态可见；不做后台偷偷录音。

口令机制看起来笨，但它把"解放双手"和"不闯祸"同时满足了——比"长按耳机键"更符合用户"不按键"的要求。

## 被否决的替代方案

- **耳机按键 / 线控长按批准**：用户明确要求不按键；且媒体键是系统共享资源，容易误触与抢占。
- **手机常驻监听**：Android 上可行，但费电、锁屏限制多，且仍然要带着手机；与"直连电脑"的诉求相反。
- **云端语音助手（Siri / 小爱）中转**：延迟高、隐私不可控、无法拿到 Agent 的上下文与授权语义。
- **只做 TTS 播报、不做语音回复**：实现最简单，但用户还是得掏手机点，等于没解放双手。

## 分阶段落地

| 阶段 | 范围 | 验收 |
|---|---|---|
| **P0** | TTS 播报 critical + 语音「同意 / 拒绝 / 重复」+ 草稿回读 + 4 位口令 | 戴耳机完成一次真实授权，全程不碰手机 |
| **P1** | 状态查询、暂停/继续、切换会话 | 连续 3 条语音指令正确路由 |
| **P2** | 自由口述任务到选中会话（STT → 草稿 → 二次确认 → 发送） | 口述一段需求，回读无误后确认，Agent 正确开跑；说「重说」可整段作废 |
| **P3** | 唤醒词常开（"mo" 之类），免按键唤起 | 误唤醒 < 1 次/小时，噪声环境可用 |

P0 是唯一必须一次做对的：它验证"声音能不能安全地替代点按"。P3 可以最后做，P0-P2 用 VAD 断句即可，不必先解决唤醒词。

## 风险与验证点（spike）

1. **AEC 自激**：TTS 从耳机出声，麦克风在同一只耳机上，必须验证 VoiceProcessingIO 能否压住回授；压不住就退化为"播报时暂停收音"。
2. **HFP 音质**：耳机麦克风一开，输出会掉到通话带宽。需实测播报可懂度是否可接受。
3. **macOS 麦克风权限**：裸 CLI 会被 TCC SIGABRT，必须打成 .app 并带用途说明；重签后权限可能重置。
4. **多设备争抢**：耳机同时连手机与电脑时的多点行为；连不上时如何自动回退到手机通道。
5. **中文 ASR 准确率**：技术词、路径、文件名是重灾区，需拿真实授权文案做测试集。
6. **延迟预算**：断句 300ms + ASR < 1s + 回读与确认，超过 2s 就会让人怀疑"它没听见"。
7. **确认疲劳**：每次都回读会让人条件反射地说「确认」。缓解办法是回读只念有后果的部分（路径、数字、动词），并在连续多次确认后抽查一次完整回读。

## P0.5：并入桌面分发包（2026-10-17）

- **模型直带**：静态链接的 `whisper-cli`（1.3MB）+ `ggml-small-q8_0`（约 264MB）打进 runtime，
  启动即可用，不做首次下载。**模型内置是 0.2.x 的明确决策，不是遗漏**：语音低频但关键，
  装完即用优先；首次下载要处理进度、校验、断点、镜像与离线失败，收益只是包体。
- **开关**：菜单栏托盘 → 语音 → 勾选「启用语音」，写 `~/.mo-agent/voice.json`，重启 host 生效；默认关闭。
  同一子菜单提供「麦克风权限设置…」与「语音测试」。
- **路径**：分发包读 `runtime/voice/`，开发态回退 `.build/`。
- **常驻 helper**：桥改为 `open` 启动一次的本地 TCP 服务（127.0.0.1 + 随机 token），
  host 用一行 JSON 发 `ping/selftest/record/quit`；不再每次录音写 `/tmp` 命令文件。
  token 与端口写在 `~/.mo-agent/voice-bridge.json`（0600），helper 空闲 5 分钟自动退出。
- **权限**：仍然是 `.app` 才拿到麦克风；这次改的是 IPC，不是 TCC 路径。
- **实测**：新 helper 走 socket 发 `record`，3 秒无语音返回 `timeout`，没有 `SIGABRT`，
  说明 IPC、权限与录音链路都通；换成有人说话即可正常识别。
- **签名**：仍是 ad-hoc。正式签名与「升级后 TCC 权限是否保留」暂缓，等有 Developer ID 再补。
- **构建开关**：`WITH_VOICE=0` 可打出不带语音资源的轻量包。
- **打包后实测**：runtime host 能直接从 `runtime/voice/` 加载，启动日志为「语音已启用」
  （不是「首次会请求麦克风」），说明同一签名副本保留了此前的 TCC 授权。
- **体积**：语音资源 254MB，分发包约 282MB。

## 最终形态（0.2.x）

在 P0.5 之后试过**方案 B：由外层 mo-agent.app 直接用原生子进程录音**，验证失败：
Electrobun 运行时会把 App 交给 cottontail 托管，TCC 责任主体变成 cottontail 而不是用户安装的
mo-agent.app，权限框与授权记录都对不上，重装/升级后行为不可预期。

因此最终保留**方案 C：嵌套 helper**——独立签名的 `mo-agent 语音.app` 作为唯一麦克风主体，
host 通过本地 TCP 调用。取舍是：

- 外层 App 仍声明 `NSMicrophoneUsageDescription`，但实际授权只落在 helper 上；
- 换 helper 或重签会让 macOS 当成新 App，权限需要重新授权一次；
- 正式 Developer ID 签名与「升级后 TCC 权限是否保留」的验证暂缓，等有证书再补；
- 模型继续内置，不做首次下载（理由见 P0.5）。

## P1 实现状态（2026-10-17）

P1 只做**命令**，不做唤醒词与常开麦克风（P3），也不做自由口述（P2）。

- **触发**：托盘「语音」→「语音命令」，click-to-talk；一次请求 = 提示语 + 听一次 + 解析 + 执行。
- **暂停/继续**：按 ADR-0001「不接管 Agent 进程」的约束，只暂停**语音播报与语音审批**，默认 15 分钟
  （`MO_AGENT_VOICE_MUTE_MINUTES` 可配），不使用 SIGSTOP/SIGCONT。审批仍进 pending，手机/终端可用；
  静音时 host 不再把语音算作在线决策端，没有手机时直接交回终端。
- **切换会话**：host 没有前台窗口，只设置「当前关注会话」（`voiceTargetSessionId`）；后续状态查询
  围绕它汇报，P2 口述任务默认发给它。不改变审批归属。
- **状态查询只读**；暂停/继续/切换先 TTS 回读，再听一次「确认/取消」，**不使用数字口令**——口令只留给审批。
- 未知、低置信度、歧义一律不执行；切换找不到或有多个候选时列出来，不猜。
- 共用 `listenOnce`（录音/VAD/ASR 一次），审批口令、次数与结束语义保持不变。

## P2 实现状态（2026-10-17）

P2 只做**自由口述任务**：STT → 草稿 → 回读 → 二次确认 → 发送。不做流式口述、语音编辑、多会话广播、
自动重试发送、唤醒词（P3）。

- **触发**：托盘「语音」→「语音口述任务」，click-to-talk；一次点击 = 一次口述请求，
  失败后由用户重新点击，不在后台偷偷继续录。
- **目标**：沿用 P1 的「当前关注会话」。有焦点且在线就用它；没有焦点时只在恰好 1 个活跃会话时自动选，
  并在回读里说「发给 X」；多个/零个候选或焦点离线一律不发送，只列候选。
  目标在口述开始时捕获，中途切换关注会话不改变本次发送目标。
- **草稿与确认**：ASR 文本先成草稿，浮层显示全文、目标与字数；只有「确认发送」/「发送」/「确认发布」
  才发送。「同意」「确定」「好」等泛化 CONFIRM 不发送；「重说」丢弃并重录一次，「取消」丢弃；
  超时、低置信度、空文本不发送。数字口令仍只留给审批。
- **发送**：只走现有 `dsh.prompt(sessionId, text, mode)`，只发一次；失败显示错误并保留草稿，
  不自动重试、不换 Agent。DSH 不可用时直接返回、不进入录音。
- **录音参数**：口述断句静音 1.6 秒、最长 30 秒、整体超时 45 秒；审批与 P1 命令默认不变。
- **静音**：P1 的「暂停语音」只静音播报/审批，不阻止用户主动口述。
- **浮层**：复用 P1 的浮层与位置记忆；结果先显示再播报；保持固定透明度，不重新引入 backdrop-filter。
  启用语音后浮层常驻（启用/重启后显示；启动时等设置窗口关闭后再显示，不再自动隐藏），
  底部提供「语音命令 / 语音口述 / 语音测试」按钮；托盘第一层提供「显示/隐藏语音浮层」切换。
- **验证**：单元测试覆盖目标规则、严格确认、重说/取消/超时、只发一次、发送失败；host 集成用假 DSH
  验证「脚本语音 → 草稿 → 确认发送」只调用一次 `session/prompt`，取消/超时调用零次，浮层 SSE
  能收到 start/target/draft/confirm/result/done。

## 与 ADR-0001 的关系

不冲突，是补强。ADR-0001 说"不接管 Agent 进程、不改变工作方式"；本决策说"连手都不用抬"。观察优先的边界不变，变的只是**人机接口从屏幕扩展到声音**。

手机端不废弃：它仍是富信息界面（看 diff、长文本、多会话总览）和语音失败时的兜底。
